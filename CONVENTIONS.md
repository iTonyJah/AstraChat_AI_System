# ПРОМПТ ДЛЯ НОВОГО ЧАТА: AstraChat MCP-PowerPoint (ВКР магистратуры)

## Роль и контекст проекта

Ты — ИИ-инженер-консультант и технический соисполнитель экспериментальной части выпускной квалификационной работы магистратуры по направлению «Машинное обучение». Прикладная задача: MCP-сервер генерации презентаций в формате pptx на платформе AstraChat. Рабочий репозиторий — iTonyJah/AstraChat_AI_System, ветка local/cpu-setup; основной репозиторий научного руководителя — NeKonnnn/Astra-Studio. Стенд: CPU-only ноутбук на Fedora с Docker; текстовые модели — облачный провайдер TIMEWEB (gemini), vision-модель — qwen3-vl-plus через DashScope. Правила работы: правки кода вносятся только через промпты для агента qwen-coder или через присланные файлы, терминалом код не трогаем; docker-команды пишутся без дефиса, то есть «docker compose»; правки строго в рамках мандата; ночные сессии обязательно завершаются коммитом и пушем.

## ЧТО БЫЛО на начало работы

Первое. Образ backend содержал MCP SDK новее, чем код: функция клиента переименована со старого имени на streamable_http_client, параметр headers из сигнатуры убран и передаётся только через собственный httpx-клиент, атрибуты pydantic-моделей переименованы из camelCase в snake_case (input_schema, is_error), кортеж стримов сокращён с трёх элементов до двух. Следствие: crash-loop бэкенда на импорте, затем оба MCP-сервера в статусе offline.

Второе. Синхронная обёртка MCP-инструментов для LangGraph принимала только именованные аргументы, а исполнитель оркестратора вызывает её с одним позиционным аргументом-строкой, из-за чего каждый шаг плана падал с TypeError.

Третье. Перехватчик генерации изображений ComfyUI воровал презентационные запросы до выбора режима чата: запрос не доходил ни до LLM, ни до MCP, пользователь видел ошибку ComfyUI, токены не тратились вовсе.

Четвёртое. Конфигурация генерации изображений читается загрузчиком только из переменных окружения с префиксом IMAGE_GEN_; блок image_generation в settings.json лоадером игнорируется, поэтому правки JSON не имели эффекта.

Пятое. Планировщик LangGraph не видел MCP-инструменты (описание инструментов было пустым), галлюцинировал имена несуществующих инструментов, выбирал неверный порядок вызовов (автогенерация без предварительного создания презентации) и не передавал обязательный аргумент pptx_path в инструмент предпросмотра.

Шестое. Апстрим основного репозитория ушёл далеко вперёд: LangGraph-оркестратор удалён, введена skills-архитектура и native function-calling, обработчики чата переписаны на тысячи строк. Прямой merge апстрима в рабочую ветку уничтожил бы наработки, поэтому принято решение ветки не сливать.

## ЧТО СДЕЛАНО

Первое. Построен слой совместимости с MCP SDK: алиас старого и нового имени функции клиента с определением версии по сигнатуре, передача заголовков через httpx-клиент для новой версии, универсальные хелперы чтения схемы входа и флага ошибки инструмента независимо от версии SDK, исправление синхронной обёртки на приём позиционного аргумента с разбором JSON-строки в именованные аргументы и диспетчей корутины на главный event loop. Затронутые файлы: backend/mcp/transports/streamable_http.py, backend/mcp/client.py, backend/mcp/compat.py, backend/mcp/langgraph_tools.py.

Второе. Чат-триггеры ComfyUI отключены на трёх уровнях: переменная окружения IMAGE_GEN_CHAT_TRIGGERS со значением false в docker-compose.yml (единственный реально работающий уровень), блок image_generation с chat_triggers_enabled false в backend/settings.json как документация намерения, и regex-фильтр презентационных интентов в backend/services/image_generation_service.py как вторая линия защиты. Проверено тестом из четырёх фраз: ни «нарисуй кота», ни «создай презентацию» больше не уходят в ComfyUI.

Третье. Планировщик LangGraph усилен: MCP-инструменты стали видимы в описании (42 прикреплённых инструмента), добавлен блок точных имён доступных инструментов, фильтр галлюцинаций имён через сверку со словарём инструментов, а в промпт планировщика внесены явные правила: запрет инструмента автогенерации для тематических презентаций и обязательный порядок «создать презентацию, добавить слайды по одному с авторским контентом, сохранить, снять предпросмотр с передачей пути из шага сохранения». Файл: backend/agents/langgraph_orchestrator.py.

Четвёртое. Достигнут бейзлайн первой версии: сквозная цепочка «планировщик — исполнитель — MCP-сервер pptx — сохранение файла — рендер предпросмотра» работает end-to-end, получены артефакты pptx и PDF, стоимость прогона около 48 тысяч входных и около двухсот выходных токенов. Контент пока шаблонный бизнес-демо, потому что инструмент автогенерации успел попасть в план до вступления запрета в силу в рантайме.

Пятое. Наведена git-гигиена: все правки закоммичены в local/cpu-setup и запушены (коммиты 01b1a01 — MCP SDK compat, 4b971ee — отключение триггеров в settings, 0fe2ba2 — переменная окружения в compose, 09ff6d7 — правила планировщика), созданы страховочные ветки backup/pre-merge-0920 и backup/local-cpu-setup-0920, на settings.json установлен бит assume-unchanged, чтобы рантайм-правки интерфейса не засоряли статус; апстрим изучен через целевые диффы, принято решение о раздельных колеях.

## ЧТО СДЕЛАТЬ, по приоритетам

Приоритет первый. Пересобрать образ backend и повторить тест «Создай презентацию из 3 слайдов про машинное обучение». Ожидание: тематический контент про машинное обучение и чистая цепочка из создания презентации, трёх добавлений слайдов, сохранения и предпросмотра, без вызова автогенерации. Помнить: после пересборки контейнерный settings.json сбрасывается, поэтому тумблеры интерфейса (агентный режим, chip MCP-PowerPoint) выставляются заново, память диалогов очищается.

Приоритет второй. Если автогенерация всё же проникает в план, ввести её жёсткий blacklist в коде бэкенда: исключать инструмент из описания активных инструментов, а не полагаться только на промпт.

Приоритет третий. Замкнуть vision-петлю в LangGraph-трассе: передавать PNG-предпросмотр слайдов в base64 агрегатору, чтобы vision-модель описывала и критиковала слайды, и обязательно санировать base64 перед финальным промптом. Сейчас инъекция изображений существует только в MCP agent loop прямого режима.

Приоритет четвёртый. Добавить телеметрию токенов оркестратора: логировать входные и выходные токены вызовов планировщика и агрегатора как метрики для диссертации.

Приоритет пятый. Поднять качество контента: требовать от планировщика писать содержимое каждого слайда самостоятельно по теме пользователя, по два-четыре пункта на слайд, запретив пустой и шаблонный контент.

Приоритет шестой. Миграция на апстрим отдельной колеёй: создать ветку try/upstream-2.2.5.5 от upstream/main, проверить MCP-PowerPoint на новой архитектуре со skills и native function-calling, портировать фильтр презентационных интентов (правка на несколько строк), оформить правила презентаций как skill с автоподключением идентификаторов инструментов; сравнить подходы для раздела диссертации о сравнении архитектур. В рабочую ветку апстрим не сливать.

Приоритет седьмой, перспектива. Параллельные суб-агенты по одному на слайд для снижения задержки и токенов; итоговый отчёт научному руководителю с метриками бейзлайна и схемой архитектуры.

## Опорные факты для нового чата

Требования научного руководителя: с августа — LLM сама выбирает инструменты без точных команд в промпте; с 20 сентября — ComfyUI не вызывается по команде из чата, только через инструменты. Оба выполнены на рабочей ветке.

Известные исторические ошибки для распознавания в логах: «No presentation is currently loaded or the specified ID is invalid» означает автогенерацию без создания презентации; «pptx_path Field required» означает предпросмотр без пути к файлу; «_make_sync() takes 0 positional arguments» означает старую сигнатуру обёртки; «streamable_http_client() got an unexpected keyword argument headers» означает старый стиль вызова нового SDK; «'Tool' object has no attribute 'inputSchema'» означает чтение camelCase-атрибута в новой SDK.

Метрики для диссертации: бейзлайн v1 — 48010 входных и 205 выходных токенов, шаблонный контент; целевой бейзлайн v2 — тематический контент, цепочка из пяти-шести вызовов, vision-проверка слайдов.

Артефакты и логи прошлых сессий лежат в домашнем каталоге astrachat_logs, пример артефакта — machine_learning_presentation.pdf с бизнес-шаблоном вместо тематики машинного обучения.
